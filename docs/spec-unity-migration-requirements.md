# Unity 移行要件・確定仕様まとめ

最終更新：確定内容を反映済み。未決定の項目のみ「要決定」として残す。

## 0. 確定した仕様（全体）

| 項目 | 決定内容 |
|------|--------|
| カスタム俳句 | **候補B（合句）**：2枚の百人一首を合体して新カード生成 |
| 詠み上げレベル | 採用。**ランをまたいで保持**（プロフィールに句ごとの使用数を記録） |
| 筆の跡 | ビジュアル装飾として実装。毛筆フォント・カードスリーブ・金地の色紙 |
| 封印（Seal） | 廃止 |
| 歌枕タイル（ジョーカー枠） | 廃止。歌枕はステージシナジーとして残す |
| プラットフォーム | **Steam（PC）**。Windows メイン、Mac は後検討 |
| カード実装方式 | **ワールドスペース スプライト**。3D アニメーションあり |
| 歌人イラスト | **戯画化アイコン**（鳥獣戯画的なデフォルメ。肖像ではない） |
| 音声 | なし。**句ごとに雅楽の効果音**を設定して個性を出す |

## 1. プラットフォーム・Steam 統合

### 1.1 確定事項

- **配布：Steam（PC）**
- 対象 OS：Windows 10/11 を必須。Mac は後から追加可能な構成にしておく
- 現行 Web アプリは Steam リリース後に廃止、または Unity WebGL 版として維持するか → **要決定**

### 1.2 Steam 統合で必要になるもの

| 要素 | 内容 | 備考 |
|------|------|------|
| Steamworks SDK 連携 | Facepunch.Steamworks または Steamworks.NET | Unity 向けにラッパーが充実 |
| Steam Cloud Save | `ISteamRemoteStorage` でセーブデータをクラウド同期 | ローカル JSON と併用でよい |
| Steam 実績（Achievements） | 「初めて憑依した」「合句を作った」などのマイルストーン | 設計は別途 |
| ストアページ素材 | カプセル画像（各サイズ）、スクリーンショット、トレーラー動画 | Steamworks 申請に必要 |

### 要決定 1-A：ビジネスモデル

| 選択肢 | 内容 |
|--------|------|
| 買い切り | シンプル。Steam 最多モデル |
| 基本無料 + 追加コンテンツ DLC | Steam での F2P は難度が高い |
| アーリーアクセス → 正式リリース | 早期収益化しながらフィードバックを得られる |

## 2. レンダリング・カード実装

### 2.1 確定事項

- **Unity URP（Universal Render Pipeline）** を使用
- カードは **ワールドスペース スプライト（SpriteRenderer）** として実装
- 3D アニメーション（カードフリップ、弧状手札、ホバー拡大）を入れる
- HUD（HP バー、バトルログ、ボタン）は **Screen Space - Overlay の Canvas** で重ねる

### 2.2 ワールドスペース カードの構造（プレハブ設計）

```
CardObject (GameObject)
  ├─ SpriteRenderer: base         // 色紙の地（詠み上げLvで素材が変わる）
  ├─ SpriteRenderer: sleeve       // スリーブ枠（レアリティ・テーマで変わる）
  ├─ SpriteRenderer: poetIcon     // 歌人アイコン（戯画）
  ├─ TextMeshPro: upperPoem       // 上の句（毛筆フォント）
  ├─ TextMeshPro: lowerPoem       // 下の句（毛筆フォント）
  ├─ TextMeshPro: poetName        // 詠み人名
  ├─ SpriteRenderer: enhancement  // 金箔・装飾オーバーレイ（透過スプライト）
  └─ Collider2D                   // クリック・ドラッグ検出用
```

### 2.3 詠み上げレベルによるビジュアル変化

| Lv | 使用回数 | 色紙 | フォント | スリーブ | 追加演出 |
|----|---------|------|---------|--------|--------|
| 0 | 0〜2 | 白地 | 明朝体 | なし | - |
| 1 | 3〜6 | 薄色紙 | 明朝体（やや太） | 細枠 | - |
| 2 | 7〜11 | 色紙（テーマ色） | 毛筆体 | 文様枠 | ドロー時に小さく光る |
| 3 | 12〜 | **金地の色紙** | 毛筆体（太） | 金縁 | プレイ時に金箔エフェクト |

### 2.4 カードアニメーション一覧

| アニメーション | 内容 | 実装方針 |
|-------------|------|--------|
| ドロー | デッキ位置から手札へ飛んでくる + フリップで表面を見せる | DOTween + Y軸回転 |
| 手札並び | 弧を描いて扇状に並ぶ | 等間隔角度計算 → DOTween |
| ホバー | マウスオーバーで拡大・手前に浮く | DOTween ScaleTo + Z移動 |
| プレイ | 手札から場の中央へ飛ぶ → 効果発動 → 捨て山へ消える | DOTween Sequence |
| レベルアップ | 金箔が広がるシェーダーアニメ + パーティクル | Shader Graph + Particle System |
| 合句（フュージョン） | 2枚が引き寄せ合い→合体→新カード出現 | DOTween Sequence |
| 憑依発動 | 画面全体が揺れ、歌人アイコンが拡大して覆う | Camera Shake + DOTween |

### 要決定 2-A：カメラ設定

| 選択肢 | 特徴 |
|--------|------|
| **平行投影（Orthographic）** | 2D 的で和紙・絵巻物に合う |
| 透視投影（Perspective）+ 浅い被写界深度 | 奥行き感。カードゲームらしい立体感 |

> ワールドスペース採用なので透視投影でも違和感ないが、和風テイストとの相性で選ぶ。

## 3. 雅楽 SFX システム

### 3.1 確定事項

- 音声読み上げなし
- 100首それぞれに**固有の雅楽効果音**（1〜3秒の短いフレーズ）を設定
- 句のテーマ・イメージに応じた楽器で個性を出す

### 3.2 楽器とテーマの対応方針

| テーマ | 主な楽器 | 音の印象 |
|--------|--------|--------|
| 春 | 笙（しょう） | 明るく柔らか、天上的 |
| 夏 | 鼓（つづみ）、龍笛（りゅうてき）高音域 | 躍動的 |
| 秋 | 篳篥（ひちりき） | 哀愁、絞り出すような音色 |
| 冬 | 龍笛（低音域）、太鼓 | 凛と、厳か |
| 恋 | 琵琶（びわ） | 情緒的、弾き語り的 |
| 哀 | 篳篥 + 笙の和音 | 重く沈む |
| 旅 | 龍笛（道中の笛） | 遠くへ向かう感じ |
| 自然 | 笙 + 琴（こと） | 広大、静謐 |

### 3.3 SFX のバリエーション付け

同テーマでも100首が同じ音では単調になるため：
- **ベース音源**（テーマ別楽器）× **フレーズバリエーション**（音高・リズムを変える）
- 例：秋テーマの篳篥でも、No.5は下降フレーズ、No.26は上昇フレーズ など
- 修辞技法によっても変化をつける（枕詞がある句はイントロに特徴音を入れる、など）

### 要決定 3-A：SFX の制作方法

| 選択肢 | 品質 | コスト |
|--------|------|--------|
| フリー素材（DOVA-SYNDROME、甘茶の音楽工房等） | 素材依存 | 無料 |
| 雅楽 MIDI 音源（東京都伝統芸能センター等のサンプル） | 中程度 | 要確認 |
| DAW + 雅楽音源プラグイン（Kontakt 等）で自作 | 高 | 音源購入費のみ |
| 演奏家に発注（短フレーズ×100） | 最高 | 費用大 |

### 3.4 BGM

- 雅楽調のアンビエント BGM をシーン別に配置（タイトル・マップ・バトル・ボス）
- SFX と BGM が重なったとき聴き映えするよう、BGM は控えめなテクスチャにする

### 要決定 3-B：オーディオ実装

| 選択肢 | 内容 |
|--------|------|
| Unity 標準 AudioSource | 小〜中規模なら十分 |
| FMOD | パラメータによる動的音制御。BGM と SFX の混合制御に強い |

## 4. 歌人アイコン（戯画スタイル）

### 4.1 確定事項

- 写実的な肖像ではなく**戯画化されたデフォルメアイコン**
- 参考イメージ：鳥獣戯画・能面的な記号化・浮世絵の略筆

### 4.2 使用箇所と必要サイズ

| 使用箇所 | 表示サイズ（目安） | 枚数 |
|---------|---------------|------|
| カード右下コーナー | 32×32 px | 100人分 |
| 詠み人フィールドスロット | 64×64 px | 同上 |
| 憑依オーバーレイ（拡大） | 256×256 px | 同上（高解像版） |
| ポップアップ・図鑑 | 128×128 px | 同上 |

> 最低 128×128 px で作っておけば縮小で使い回せる。

### 4.3 アイコンの差別化要素

同じ戯画スタイルでも100人が区別できるよう：

| 属性 | 視覚的特徴 |
|------|----------|
| rank: legendary | 金の後光・豪華な冠 |
| rank: epic | 銀縁・格調ある装束 |
| hasTonsure（出家） | 袈裟・丸坊主 |
| hasExile（流罪） | 縄・陰のある表情 |
| isRokkkasen（六歌仙） | 6角の星紋 |
| gender: female | 扇・十二単のシルエット |
| 天皇 rank | 御簾・菊の御紋 |

### 要決定 4-A：アート制作方法

| 選択肢 | 内容 |
|--------|------|
| 外注（イラストレーター） | 統一感が出る。費用・納期が発生 |
| AI 生成（DALL-E / Stable Diffusion）+ 加工 | 早い。品質のばらつきがある |
| 自作 | 完全なコントロール。時間が必要 |

## 5. データ設計・セーブ（Unity 移植）

### 5.1 詠み上げレベルのプロフィール保存

ランをまたいで usedCount を保持するため、`PlayerProfile` に追加が必要：

```csharp
[Serializable]
public class PlayerProfile
{
    public int version = 1;
    public Dictionary<int, int> poemUsedCounts; // 句番号 → 累計使用数
    public Dictionary<string, int> upgradeLevels;
    public int totalScoreEarned;
    public int runsCompleted;
    // ...
}
```

ランが終了するたびに「そのランで使った各カードの usedCount の差分」をプロフィールに加算する。

### 5.2 データフォーマット → JSON + Steam Cloud

- 句データ・歌人データ：`Resources` フォルダ内の JSON（既存 TS から変換）
- プロフィール・プロフレス：`Application.persistentDataPath/save.json` + Steam Cloud 同期

### 5.3 合句データの保存

合句カードは元カード2枚の情報を持つため：

```csharp
[Serializable]
public class CardData
{
    public int poemNumber;
    public string enhancement;         // 筆の跡の種類
    public bool isFused;
    public int[] sourcePoems;          // 合句の場合：合体元の句番号[2]
}
```

プロフィールに「現在所有している合句の一覧」を保存する。

## 6. アーキテクチャ方針

### 6.1 推奨構成

現行 TS の「純粋関数 + pub/sub ストア」設計は Unity でも活かせる。

```
GameManager（シングルトン）
  ├─ RunStateManager     // RunState の保持・更新（dispatch 相当）
  ├─ BattleResolver      // 戦闘計算（純粋 static メソッドとして移植）
  ├─ CardFactory         // カード生成
  ├─ DeckAnalyzer        // シナジー計算
  ├─ ProfileManager      // プロフィール読み書き
  └─ AudioManager        // SFX 再生（句番号 → AudioClip のルックアップ）

UI（MonoBehaviour）
  ├─ BattleScreen
  ├─ MapScreen
  ├─ PoetFieldPanel      // 詠み人フィールド
  ├─ HandController      // 手札のワールドスペース管理
  └─ CardView            // 1枚のカードの表示・アニメーション担当
```

### 6.2 シーン構成（案）

| シーン | 内容 |
|--------|------|
| `Boot` | データ読み込み・プロフィールロード |
| `Title` | タイトル画面 |
| `StageSelect` | 歌枕ステージ選択 |
| `InitialDraft` | ラン開始時の初期ドラフト |
| `Run` | マップ + バトル + ドラフト + イベント + ショップをすべて含む主要シーン |
| `Upgrade` | ラン外の強化の間 |
| `FusionScreen` | 合句制作専用（`Run` シーンのオーバーレイでも可） |
